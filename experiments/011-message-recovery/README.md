# 011 message recovery fixture

This is a bounded local model for chat request receipts and cursors. It uses Node 24 `node:sqlite`, Node's built-in TypeScript stripping, and no third-party package. `RecoveryStore.createTemporary()` creates and owns a unique directory directly under the OS temporary root; there is no caller-supplied path constructor. Reopen checks the regular-file link count, fixture `application_id`, schema version, and exact table columns before it reads or writes. It refuses to recreate a missing database. Run it with `npm run scenario` or `node --experimental-strip-types ./scenario.ts` from this directory.

The store writes one fixture message, one scoped receipt, and one scoped event in a single `BEGIN IMMEDIATE` transaction. A receipt is returned only after `COMMIT`. Its unique key is the full scope plus `requestId`. The model computes SHA-256 over a JSON-encoded fixed-order array of the exact scope fields and the UTF-8 fixture body. A retry with the same body and scope returns the saved receipt; changing the body under that ID fails. A pre-commit crash rolls all three rows back. A simulated crash after commit but before return leaves a durable receipt for the retry after reopening the database. Receipt and event counts have fixed bounds; when full, new writes fail closed and retained receipts are not evicted.

The cursor domain is `(hostId, userId, deviceId, grantId, capability, hostEpoch, authEpoch, grantEpoch)`. Authorization is checked before request content validation or event lookup. Sequence allocation and reads use only the exact authorized scope, so another scope does not consume its cursor. A changed scope or epoch, cursor beyond the available stream, or an event gap returns `snapshot-required`. This model reports that state only; it does not build or transmit a snapshot.

The scenario uses only blank fixture strings and creates a fresh `fixture.sqlite` under an OS temporary directory. It removes that owned directory in `finally`. The harness alone uses an explicitly named fixture-corruption method to create a cursor gap. It has no account, product cryptography protocol, WebSocket, ECS, terminal, OS process, or product database integration. It does not migrate or inspect a user database, and it does not persist ECS state. The hash uses Node’s standard SHA-256 implementation, with a fixture-only canonical encoding. It is not a production wire canonicalization or cryptographic protocol.

This evidence is limited to the SQLite fixture model and the scenarios in `scenario.ts`. It does not implement a production `openbot.db` transaction or complete client recovery, and it does not close WSS gates. Real authorization, lease verification, durable product cursor ownership, snapshot generation, protocol framing, identity, and device recovery remain outside this experiment. The focused scenario and this directory’s TypeScript project completed on Node v24.22.1 with SQLite 3.53.4. The scenario reports `011-message-recovery fixture scenarios passed`; the recorded command evidence is in `validation-evidence.txt`.
